WHAT IT IS

Syn9 is a trust layer for agent workflows that turns multi-source research into shared, verifiable memory.

It exposes a set of primitives — WEAVE, RECALL, REVOKE, PERMISSION_GRANT — that let agent pipelines write findings with cryptographic attribution, retrieve them with permission gating, and detect contradictions between independent sources automatically.

You interact with it via the OKX AI marketplace. No SDK to install. No infrastructure to run.

USEFUL FOR

DeFi research pipelines

Multiple price feeds contributing to a single scored opportunity. Syn9 preserves what each feed reported and surfaces where they diverge.

Multi-agent decision workflows

When multiple agents contribute to a downstream decision, Syn9 preserves each finding and its place in the chain of reasoning.

Audit and compliance trails

For workflows that need to show what data was used, in what order, and who accessed it at each step.

Contradiction detection

When independent sources disagree, Syn9 detects the divergence, preserves both findings and surfaces the contradiction without blocking the workflow.

Permissioned data sharing

One agent's findings become selectively readable by another. Access is granted by the original writer when needed, rather than fixed at configuration time.

CAPABILITIES

Research Cycle

— POST /v1/research-cycles

Runs a full multi-source research pipeline in one call. Fetches independent price or data feeds, records each with provenance, detects contradictions, and returns a structured opportunity brief.

Priced per cycle. Standard and Deep tiers available.

View on OKX AI →

WEAVE

— POST /v1/threads/:threadId/weave

Write a finding to a thread with cryptographic attribution and permission scoping. Each write is chained to the previous entry.

Available as part of the Core API.

RECALL

— POST /v1/threads/:threadId/recall

Semantic retrieval over woven findings, gated by the permission model set at write time. Supports AI synthesis of permitted results.

Available as part of the Core API.

PERMISSION_GRANT

— POST /v1/threads/:threadId/entries/:id/grant

Grant a specific identity read access to a specific entry, after the fact. The original writer controls access; the grant is additive and audited.

Available as part of the Core API.
